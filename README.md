# History AI Tutor - RAG сервис для консультирования по истории

## Описание проекта

Проект представляет собой MVP интеллектуального консультанта по истории, реализующего концепцию RAG (Retrieval-Augmented Generation). Сервис отвечает на вопросы пользователей, используя загруженные документы (учебник по истории 5 кл., Мединский ), и поддерживает контекст диалога благодаря механизму хранения сессий.

Архитектура построена на связке LangChain с локальными LLM через Ollama. Сервис представлен на FastAPI для интеграции с внешними приложениями.

## Технологический стек

- Python 3.12
- LangChain / LangChain Community (RAG, chains, память)
- FastAPI 
- Chroma DB
- Ollama (qwen3:8b, nomic-embed-text)
- Pydantic 
- Uvicorn

## Общая схема работы сервиса

### 1. Схема работы RAG-агента (rag_agent.py)

**Загрузка и обработка текста:**
- Текст разбивается на чанки через RecursiveCharacterTextSplitter

**Эмбеддинги и векторное хранилище:**
- Используется OllamaEmbeddings с моделью nomic-embed-text (небольшая в объеме , но имеет хорошие показатели при работе с векторными данными)
- Используется векторная БД Chroma 

**LLM и генерация:**
- Модель qwen3:8b через ChatOllama с температурой 0.5
- Для отладки выводится количество найденных релевантных документов и их превью
- Для уменьшения вероятности галюцинаций, в промпт добавлены запреты на выход за рамки контекста, а в случае отсутсвия информации задан специальный ответ который нейросеть может использовать, что облегчает выбор ответа


**RAG-цепочка с памятью:**
- Построена на RunnableWithMessageHistory для хранения диалогов по session_id
- Важно! Промпт запрещает LLM отвечать без контекста из учебника, для избегания галюцинаций, учитывая некритические знания у учеников
- Поддерживается функция get_context, извлекающая до 3 наиболее релевантных чанков

**Режимы работы:**
- RAG + память: полноценный поиск по документам
- Только память: обычный чат без поиска (для сравнения качества)

### 2. FastAPI сервис (main.py)

**Endpoints API:**
```
/ask (POST) - Задать вопрос боту с поддержкой сессий
/add_document (POST) - Добавить новый документ в векторную БД 
/health (GET) - Проверка работоспособности сервиса 
/stat (GET) - Получение статистики запросов 
/sessions (GET) - Список активных сессий 
/session/{session_id} (GET) - Очистить память конкретной сессии 
/reload (GET) - Перезагрузить векторную БД из файла 
```

**Модели данных (Pydantic):**
- QuestionRequest: question (обязательно), session_id (опционально), stream (заглушка)
- QuestionResponse: session_id, question, answer, timestamp, rag_used, processing_time
- AddDocumentRequest: content, metadata
- HealthResponse, StatResponse, SessionInfo для мониторинга

**Управление сессиями:**
- При отсутствии session_id генерируется новый UUID
- История сообщений хранится в словаре store (InMemoryChatMessageHistory)
- Поддержка команды очистки сессии через DELETE /session/{session_id}

### 3. Статистика и мониторинг

**Собираемые метрики:**
- Общее количество запросов (total_requests)
- Среднее время ответа в миллисекундах (avg_response_time_ms)
- Количество запросов за последнюю минуту (last_minute_requests)
- Распределение запросов по часам (requests_by_hour)
- Статистика по сессиям: количество запросов, время первого и последнего обращения

**Health check:**
- Проверка инициализации RAG системы
- Проверка доступности Ollama (через тестовый invoke)
- Подсчёт количества документов в векторной БД
- Количество активных сессий

### 4. Интеграции и зависимости

**Требования к окружению:**
- Установленный Ollama с моделями qwen3:8b и nomic-embed-text
- Python 3.12+

## Инструкции по запуску и проверке работы

## Установка 
- Скачайте репозиторий 
- Установите python 3.12 с pip
- Установите виртуальное окружение - venv 
```
python3 -m venv venv
```
- Активируйте виртуальное окружение
```
source venv/bin/activate
```
- Установите зависимости из requirements.txt 
```
pip install -r requirements.txt
```


### Запуск сервиса. 1 вариант - консольный режим. Локальный запуск RAG агента
    Для локального запуска из консоли команда: python rag_agent.py

После запуска доступны команды:
- После старта сервиса, будет выведено условное выражение "Вы: ", далее можете написать свой вопрос или задание
- exit или quit - выход
- new - очистить память текущей сессии

### Запуск сервиса. 2 вариант - FastAPI сервис

запустите файл main.py в корне проекта
```
python3 main.py
```

### Проверка API через Swagger

Для использования Swagger UI, убедитесь что FastAPI сервис запущен и откройте: http://localhost:8000/docs , выберите соответствующий endpoint и протестируйте.

### Проверка API через curl

**Health check:** curl http://localhost:8000/health

**Задать вопрос:**
curl -X POST http://localhost:8000/ask
-H "Content-Type: application/json"
-d '{"question": "Когда началась Сталинградская битва?"}'


**Задать вопрос с указанием сессии:**
curl -X POST http://localhost:8000/ask
-H "Content-Type: application/json"
-d '{"question": "А когда она закончилась?", "session_id": "user_123"}'


**Получить статистику:** curl http://localhost:8000/stat


**Очистить сессию:** 
curl -X DELETE http://localhost:8000/session/user_123


**Добавить документ из консоли:**

curl -X POST http://localhost:8000/add_document
-H "Content-Type: application/json"
-d '{"content": "Битва на Курской дуге произошла в июле 1943 года.", "metadata": {"source": "user_added"}}'



**Перезагрузить векторную БД:** curl http://localhost:8000/reload
